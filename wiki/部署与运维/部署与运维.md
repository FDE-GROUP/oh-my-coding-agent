## 简介
本指南面向生产环境的部署与运维，覆盖容器化部署（Docker、微 VM、沙箱）、Linux 系统原生部署（systemd）、生产环境配置、监控与日志收集、自更新机制、版本管理、故障恢复、性能优化、安全加固与备份恢复等主题。仓库提供多种隔离运行模式与发布流水线脚本，以及 systemd 服务单元，便于构建可重复、可审计、可回滚的交付物。

## 项目结构
仓库采用多包工作区组织，包含平台入口应用、Pi Web UI、扩展骨架、AI/Agent/TUI 等核心包以及大量构建与发布脚本。与部署运维直接相关的部分包括：
- 平台入口应用：用于在 monorepo 中启动 Pi 并注入平台环境变量。
- Pi Web UI：独立的浏览器客户端，提供 systemd 服务单元和完整的生产部署支持。
- 容器化文档与 Dockerfile：提供多种隔离运行方式与评估器镜像构建。
- 发布与打包脚本：负责制品生成、本地安装验证、发布元数据与最新版本指针更新。

### systemd 服务部署与环境变量配置
**新增** 支持 Linux 系统的 systemd 服务单元，提供生产级服务管理功能。

- 服务单元特性
  - 自动启动与开机自启：`WantedBy=multi-user.target`
  - 失败自动重启：`Restart=on-failure`，重启间隔 3 秒
  - 工作目录管理：指定应用根目录
  - 环境变量配置：支持配置文件路径、Node.js 环境等
  - 网络依赖管理：`After=network.target`

- 环境变量配置
  - `PI_WEB_CONFIG`：配置文件路径，默认 `~/.pi-web/config.json`
  - `NODE_ENV`：运行环境，生产环境设为 `production`
  - `PI_WEB_PI_BIN`：可选的 Pi 可执行文件路径

### Pi Web UI 生产环境配置
**新增** 完整的 Pi Web UI 生产环境配置支持，包括访问控制、安全加固和多用户管理。

- 访问控制与安全
  - 绑定地址控制：只监听 `127.0.0.1` 时无需认证，非回环地址必须配置用户
  - 令牌认证：使用 HttpOnly、SameSite=Strict 的 cookie
  - 登录限速：同一来源每分钟最多 10 次尝试
  - HTTP 安全头：CSP、nosniff、frame-ancestors 'none'

- 配置管理
  - 配置文件权限：0600，仅所有者可读写
  - 自动生成密钥：首次启动时生成 auth.secret
  - 工作区白名单：限制用户可访问的工作区
  - 运行时限制：每用户和全局并发上限

### 容器化与沙箱部署
- 隔离方案对比
  - Plain Docker：整个 Pi 进程在容器中运行，适合简单本地隔离。
  - Docker Sandboxes：托管沙箱，代理替换凭证，避免真实密钥进入沙箱。
  - OpenShell：文件系统、进程、网络、凭证与推理策略控制，支持远程网关。
  - Gondolin：本地微 VM，仅路由内置工具与命令，保留宿主接口。
- 关键注意事项
  - 只暴露任务所需的工作目录、凭证与网络目的地。
  - 使用只读挂载或复制进出以避免写回宿主机。
  - 工具级隔离不约束宿主 Pi 或未走隔离后端的扩展工具。

## 依赖关系分析
- 组件耦合
  - 平台入口对 Pi 运行时是单向依赖，职责单一，便于扩展平台能力而不侵入核心。

## 性能考虑
- 构建与缓存
  - 使用离线模型数据构建以减少网络抖动与重复下载。
  - 利用构建缓存加速依赖安装与编译。
- 运行期资源
  - 在容器/沙箱中限制 CPU/内存配额，避免影响宿主与其他租户。
  - 合理设置 I/O 与网络超时，防止长尾请求拖慢整体吞吐。
  - systemd 服务中使用资源限制配置，防止单实例占用过多资源。
- 镜像体积
  - 使用 slim 基础镜像，按需安装系统依赖。
  - 移除不必要的文档与示例以减小镜像体积。
- 并发控制
  - Pi Web UI 支持每用户和全局运行时并发限制。
  - 合理配置 `maxRuntimesPerUser` 和 `maxRuntimesTotal`。

## 故障排查指南
- systemd 服务问题
  - 检查服务状态：`systemctl status pi-web`
  - 查看服务日志：`journalctl -u pi-web -f`
  - 验证配置文件路径和环境变量设置
  - 确认服务文件和依赖项权限正确
- 容器/沙箱无法访问工作目录
  - 检查是否挂载了正确的只读/读写目录。
  - 确认容器内工作目录与宿主映射一致。
- 凭证泄露或不可用
  - 在 Plain Docker 中确认凭证通过环境变量传入。
  - 在 Docker Sandboxes 中确认代理已正确替换凭证占位符。
  - 在 OpenShell 中确认推理端点指向网关暴露的兼容接口。
- 发布失败或指针未更新
  - 校验安装包与锁文件版本一致性。
  - 检查 latest.json 原子推进条件是否满足。
- 本地安装异常
  - 确认使用 --ignore-scripts 安装，避免生命周期脚本干扰。
  - 核对 artifactSet 清单与消费者 package.json 的一致性。
- Pi Web UI 访问问题
  - 检查配置文件语法和权限（0600）
  - 验证工作区路径存在且为目录
  - 确认认证配置和用户 token 哈希正确
  - 检查防火墙和网络端口配置
