模块以 `src/` 为唯一源码入口，按职责拆分为四个文件：
- `types.ts`：集中定义所有对外类型（`AgentMessage`、`AgentTool`、`AgentEvent`、`AgentLoopConfig`、`StreamFn`、`BeforeToolCallContext` 等），是模块的类型契约。
- `agent-loop.ts`：低层循环实现，暴露 `agentLoop` / `agentLoopContinue` / `runAgentLoop` / `runAgentLoopContinue`，负责声明 tool 变更、驱动 `prepareNextTurn` / `getSteeringMessages` / `getFollowUpMessages` 钩子、串行或并行执行工具调用，并通过 `EventStream<AgentEvent, AgentMessage[]>` 向外推送事件。
- `agent.ts`：高层 `Agent` 类，维护 `MutableAgentState`（messages/tools/systemPrompt/streamingMessage/pendingToolCalls/errorMessage），内置 `PendingMessageQueue` 支持 `all` / `one-at-a-time` 两种队列模式，并桥接 `convertToLlm`、`transformContext`、`beforeToolCall`、`afterToolCall`、`finishTurn`、`prepareRequest`、`prepareNextTurn` 等钩子到 `agent-loop.ts`。
- `proxy.ts`：提供 `streamProxy`，将 LLM 请求代理到远端 `/api/stream` SSE 接口，客户端重建 `AssistantMessage`，用于服务端托管认证场景。
- `stream-fn.ts`：全局默认 `StreamFn` 注册表，通过 `setDefaultStreamFn` 注入宿主提供的模型运行时，避免对具体 provider 产生硬依赖。

依赖方向单向：`agent.ts` → `agent-loop.ts` → `stream-fn.ts`；三者共同消费 `types.ts` 与 `@earendil-works/pi-ai`。`index.ts` 仅做 re-export，`dist/` 由 `tsc -p tsconfig.build.json` 产出，`package.json` 暴露 `@earendil-works/pi-agent-core` 包名与 ESM 导出。
