模块按职责拆分为四个子域：
- 凭据存储层（auth-storage.ts）：实现 `CredentialStore`，通过 `AuthStorageBackend` 抽象出文件/内存后端；`FileAuthStorageBackend` 使用 `proper-lockfile` 对 `auth.json` 加锁读写并支持 EPERM/ELOCKED 重试，`ReadOnlyAuthStorage` 提供只读视图，`InMemoryAuthStorageBackend` 用于测试；`AuthStorage` 维护共享的 `readState` 缓存并通过 `getFileRevision` 检测外部变更。
- 运行时覆盖层（runtime-credentials.ts）：`RuntimeCredentials` 作为装饰器在持久化存储之上叠加进程内 `Map` 覆盖，追踪 pending OAuth 刷新以便 `settled()` 等待落盘完成。
- 项目信任层（trust-manager.ts + project-trust.ts）：`ProjectTrustStore` 以 `trust.json` 持久化目录级信任决策，`hasTrustRequiringProjectResources` 扫描 `.pi/settings.json`、`.agents/skills` 等敏感资源触发信任流程；`resolveProjectTrusted` 编排扩展事件、默认策略与 UI 交互。
- 辅助层：`auth-guidance.ts` 生成用户提示文案，`client-identity.ts` 组装 `ClientIdentity`（含 `PI_ATTRIBUTION`），`key-id-schema.ts` 基于 TypeBox 定义快捷键绑定校验模式。
依赖方向单向向外：本模块被上层 runtime 消费，不反向依赖业务逻辑。
