模块按职责分层组织：
- 配置层 `model-config.ts`：基于 TypeBox schema 校验并冻结 `models.json`，提供只读的 `ModelConfig` 快照。
- 组合层 `provider-composer.ts`：将内置 Provider（来自 `@earendil-works/pi-ai/providers/all`）、`models.json` 的 `models`/`modelOverrides`、扩展 `ProviderConfigInput` 三层叠加，生成带 API Key / OAuth 鉴权与模型覆盖的 `Provider`；同时导出 `resolveCompatibilityRequestConfig` 供兼容层使用。
- 运行时层 `model-runtime.ts`：核心 `ModelRuntime` 持有 `pi-ai` 的 `createModels`、`RuntimeCredentials`、`ModelConfig`、`ModelsStore`、虚拟模型表与 compositionErrors；负责 provider 重建、可用性快照 (`all`/`available`)、凭据操作队列、以及 `stream`/`complete`/`classify`/`generateImages` 等请求入口，通过 `prepareRequest` 注入鉴权与 headers。
- 持久化层 `models-store.ts`：实现 `ModelsStore`，提供内存版 `InMemoryCodingAgentModelsStore` 与带文件锁 + 版本缓存的 `FileModelsStore`（共享 `sharedModelsFileReadState`）。
- 匹配与解析层 `model-resolver.ts`：实现 `resolveModelReference`，支持 `provider/id`、模糊匹配、`:<thinking>` 后缀、glob 模式，输出 `resolved`/`ambiguous`/`not-found` 三种结果；并提供 CLI 入口 `resolveCliModel` 与初始模型选择 `findInitialModel`/`restoreModelFromSession`。
- 虚拟模型层 `virtual-models.ts`：定义 `VirtualModelDefinition`，用 `VIRTUAL_MODEL_API="pi-virtual"` 标记路由占位模型，`withVirtualModels` 把虚拟模型挂到 provider catalog 上但不参与实际流式调用。
- 门面层 `model-registry.ts`：`ModelRegistry` 是同步 facade，所有方法转发给 `ModelRuntime`，向扩展暴露 `getApiKeyAndHeaders`、`registerProvider`、`registerVirtualModel` 等 API。
- 辅助工具：`provider-matching.ts` 提供大小写无关的 provider 名称匹配；`model-runtime.ts` 还集成 `remote-catalog-provider.ts` 与 `runtime-credentials.ts` 完成远程目录与凭据管理。
依赖方向单向：registry → runtime → (composer, config, store, virtual-models, remote-catalog)，resolver 仅消费 runtime 的只读视图。
