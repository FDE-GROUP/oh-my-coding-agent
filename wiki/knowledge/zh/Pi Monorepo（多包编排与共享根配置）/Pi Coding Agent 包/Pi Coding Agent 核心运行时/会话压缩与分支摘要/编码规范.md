- LLM 调用统一经由 `completeSummarization` 包装，自动注入 `cacheRetention: 'none'` 与随机 `sessionId`，并由 `retryAssistantCall` 处理瞬态重试。
- 对摘要结果先通过 `getSummarizationFailure` 检查 `error`/`length`/`aborted` 停止原因，再校验响应中是否包含 `toolCall` 块，否则抛出或返回错误。
- 文件操作追踪采用两阶段模式：先用 `createFileOps` + `extractFileOpsFromMessage` 收集 read/written/edited Set，最后用 `computeFileLists` 去重输出 `readFiles`/`modifiedFiles` 列表。
- 发送给 LLM 的对话一律先经 `convertToLlm` 转为 provider 消息，再用 `serializeConversation` 序列化为带 `[User]`/`[Assistant]`/`[Tool result]` 标签的纯文本，避免模型继续对话。
- token 估算统一使用 `estimateTokens`（chars/4 启发式），并在需要预算控制时结合 `shouldCompact` / `reserveTokens` 判断触发条件。
