模块以 `define.ts` 中的 `ProviderDefinition` 接口为契约：每个 provider 文件（`providers/*.ts`）通过 `defineProvider` 声明自身，并在 `providers/index.ts` 的 `PROVIDERS` 数组中集中注册；`sources/` 负责从 models.dev、OpenRouter、Vercel AI Gateway、NVIDIA NIM、Radius 等外部 API 拉取原始数据，统一封装为 `CatalogSources`。

构建管线分两层：
- `build.ts` 的 `buildCatalog` 是核心流水线：对每个 provider 依次执行 `models()` → `compat` 默认值合并 → `families/*` 共享规则（Claude/DeepSeek/OpenAI 家族、DeepSeek 兼容层）→ `finalize()/finalizeAll()` → 图片输入限制归一化 → 输出 `{chat, image, classifier}` 三张表。
- `generate.ts` 是 CLI 入口（`#!/usr/bin/env node`），调用 `loadCatalogSources` + `buildCatalog`，将结果写入 `src/providers/data/<provider>.json` 并按 provider 生成 `<id>.models.ts` 分片与 `src/models.generated.ts` 聚合器，使用临时目录 staging + rename 保证原子替换。

`scripts/` 提供辅助工具：`hydrate-model-catalog.ts` 从已发布的 `models.all.json` 离线反序列化出 data 目录；`model-data.ts` 提供分组、manifest 校验等共享逻辑；`check-model-data.ts` / `generate-test-image.ts` 用于质量检查与测试素材生成。

依赖方向单向：`providers/*` → `sources/*` → 外部网络；`build.ts`/`generate.ts` 消费二者；`scripts/*` 仅依赖 `catalog` 与 `model-data.ts`，不反向依赖 providers。
