简介

本文件面向“会话管理”这一核心能力，覆盖以下目标：

  • 会话的创建、命名、保存、恢复、分叉和删除。
  • 命令行参数 --continue、--resume、--session、--fork、--session-id、--session-dir、--no-session、--name 的行为与约束。
  • 会话文件的存储位置、JSONL 格式、版本迁移与树形结构。
  • 新增 只读共享系统，支持基于 token 的安全分享和过期管理。
  • 新增 管理员访问控制，提供审计日志和会话管理能力。
  • 新增 交接文档生成，自动提取会话关键信息并脱敏敏感数据。
  • 会话生命周期管理、跨项目共享与管理、数据迁移与备份建议。

架构总览

会话管理的整体流程如下：

  1. 解析 CLI 参数，决定会话策略：新建、继续、恢复、分叉、无会话。
  2. 根据策略选择或创建 SessionManager。
  3. 确定最终工作目录（cwd），并加载对应项目的信任状态与服务。
  4. 进入交互模式、RPC 模式或打印模式。
  5. 用户通过 /resume、/new、/fork、/import 切换会话；或通过 CLI 参数控制启动行为。
  6. 会话以 JSONL 形式持久化，支持树形分支、压缩摘要、标签、名称等元数据。
  7. 新增 通过 Web API 创建只读分享链接，支持 token 认证和过期管理。
  8. 新增 生成交接文档，自动提取会话关键信息并脱敏敏感数据。

详细组件分析

会话创建、命名与保存

  • 创建会话：
    • 默认通过 SessionManager.newSession() 生成会话头，包含会话 ID、时间戳、cwd、父会话路径等。
    • 如果启用持久化，会基于 sessionDir 和时间戳+会话 ID 生成 .jsonl 文件路径。
  • 命名会话：
    • 通过 appendSessionInfo(name) 追加 session_info 条目，名称会被清洗并去换行。
    • 可通过 CLI -n/--name 设置初始名称，或在交互中使用 /name。
  • 保存会话：
    • 首次写入发生在出现 user 或 assistant 消息后；仅系统提示、模型变更等不会立即落盘。
    • 后续追加采用 append-only 写入，避免破坏历史。

会话恢复：–continue、–resume、–session

  • --continue：
    • 恢复当前目录最近的会话。
    • 工作目录为当前目录。
  • --resume：
    • 打开会话选择器，允许从所有目录中选择会话。
    • 恢复后会切换到该会话的工作目录运行。
  • --session <path|id>：
    • 通过文件路径或完整/部分会话 ID 打开会话。
    • 如果 ID 匹配的是其他目录的会话，可询问是否在当前目录分叉。
    • 恢复后会切换到该会话的工作目录运行。

会话分叉：–fork、–session-id

  • --fork <path|id>：
    • 根据路径或 ID 选择一个现有会话，将其内容复制到当前目录的新会话中。
    • 不能与 --session、--continue、--resume、--no-session 同时使用。
  • --session-id <id>：
    • 指定新会话的 ID。
    • 不能与 --session、--continue、--resume 同时使用；可与 --fork 组合为新分叉会话指定 ID。

会话删除与清理

  • 交互式删除：
    • 在 /resume 中选择会话并按快捷键触发删除确认。
    • 优先尝试 trash CLI；失败则回退到直接删除。
    • 当前活动会话不允许删除。
  • 手动删除：
    • 可直接删除 ~/.pi/agent/sessions/ 下的 .jsonl 文件。

会话文件存储位置与格式

  • 默认存储位置：
    • ~/.pi/agent/sessions/--<path>--/<timestamp>_<session-id>.jsonl
    • <path> 中的 /、\、: 会被替换为 -。
  • 环境变量与配置覆盖：
    • PI_CODING_AGENT_SESSION_DIR 可覆盖默认目录。
    • --session-dir 优先级最高。
    • sessionDir 设置项也可配置。
  • 文件格式：
    • JSONL，每行一个 JSON 对象。
    • 首行为 session 头，包含 type、version、id、timestamp、cwd、parentSession。
    • 后续为各类 entry：message、model_change、thinking_level_change、usage、compaction、branch_summary、custom、custom_message、context_edit、label、session_info。
    • 通过 id/parentId 形成树结构，leaf 表示当前位置。

会话生命周期与上下文构建

  • 会话生命周期：
    • 启动阶段选择会话。
    • 运行时追加消息、模型变更、思考级别变更、用量统计、压缩摘要、分支摘要、自定义扩展数据、上下文编辑、标签、会话信息等。
    • 关闭时若未产生对话消息，可能不写文件。
  • 上下文构建：
    • buildContextEntries() 沿 leaf 到 root 的路径收集活跃 entry，处理 compaction。
    • buildSessionProjection() 应用最新的 context_edit，返回投影后的消息与来源。
    • buildSessionContext() 输出给 LLM 的消息列表、thinkingLevel、model。

只读共享系统

新增 系统提供了安全的会话分享功能，支持基于 token 的访问控制和过期管理：

  • 分享创建：

    • 通过 createShare(sessionId, owner, ttlMs) 创建分享链接。
    • 生成随机 token，存储 SHA-256 哈希值而非明文。
    • 默认 7 天过期，可配置有效期（1-30 天）。
    • 文件权限设置为 0600，确保安全性。

  • 访问控制：

    • 通过 findValidShare(token) 验证分享有效性。
    • 检查 token 是否存在、未撤销、未过期。
    • 支持通过 token 或 token hash 进行撤销操作。

  • Web API 接口：

    • POST /api/sessions/:sessionId/shares：创建分享链接。
    • GET /api/sessions/:sessionId/shares：列出会话的所有分享。
    • DELETE /api/shares/:token：撤销分享链接。
    • GET /api/shares/:token：获取分享快照数据。

  • 前端界面：

    • SharePanel 组件提供创建、查看、撤销分享的功能。
    • 分享页面 /share/:token 提供只读视图。
    • 支持实时事件流更新，展示会话最新状态。

交接文档生成

新增 系统能够自动生成会话交接文档，提取关键信息并提供安全的数据保护：

  • 信息提取：

    • 从会话消息中提取用户目标和助手结论。
    • 识别工具调用及其参数摘要。
    • 追踪修改的文件路径。
    • 提取风险信息和下一步计划。

  • 安全脱敏：

    • 自动检测并隐藏敏感信息（API 密钥、令牌、私钥等）。
    • 对长命令和参数进行截断处理。
    • 过滤系统消息，只保留有用信息。

  • 文档结构：

    • 标题：基于第一个用户消息生成。
    • 基本信息：会话 ID、工作区、所有者、模型信息。
    • 目标：用户的主要需求。
    • 结论：助手的最终总结。
    • 工具调用：调用的工具和结果统计。
    • 改动文件：修改的文件列表。
    • 风险与下一步：潜在风险和后续工作。

管理员访问控制

新增 系统提供了完善的管理员功能，支持会话管理和审计：

  • 权限验证：

    • readSessionAccess()：验证读取权限（所有者或管理员）。
    • sessionAccess()：验证写入权限（仅所有者）。
    • 支持本地用户和远程用户的不同权限模型。

  • 审计日志：

    • 记录所有重要操作：分享创建、撤销、会话管理等。
    • 包含用户 ID、角色、操作类型、目标资源、结果等信息。
    • 支持分页查询和过滤。

  • 管理接口：

    • GET /api/admin/sessions：查看所有会话（包括所有者信息）。
    • GET /api/admin/audit：查看审计日志。
    • 管理员可以读取非自己拥有的会话。

会话分享与跨项目共享

  • 导出：
    • 可将当前会话导出为 JSONL 或 HTML。
    • 分享时会附加 pi.share 自定义 entry，携带 systemPrompt 与 tools 描述。
  • 分享渠道：
    • 优先尝试 Radius artifact；未配置时回退到 GitHub Gist。
    • 需要 GitHub CLI 登录。
  • 跨项目共享：
    • 通过 /export、/share 生成链接或文件，供他人查看。
    • 注意会话可能包含敏感信息，分享前需审查。

性能与可扩展性

  • 会话发现与列表：
    • 并发加载会话信息，限制最大并发数，避免 IO 风暴。
    • 支持进度回调，便于 TUI 逐步渲染。
  • 大文件读取：
    • 使用缓冲读取与流式解析，避免一次性加载整个文件。
    • 头部扫描有字节上限，防止超大 header 导致阻塞。
  • 追加写入：
    • 首次写入会话头，后续追加消息，减少随机写。
  • 扩展点：
    • CustomEntry 与 CustomMessageEntry 允许扩展持久化自身状态或注入上下文。
    • CompactionEntry 与 BranchSummaryEntry 支持压缩与分支摘要，控制上下文大小。
  • 新增 分享系统性能优化：
    • 内存缓存分享记录，减少磁盘 I/O。
    • 原子文件写入，确保数据一致性。
    • Token 哈希存储，提升查询性能。
  • 新增 交接文档生成优化：
    • 流式处理会话消息，避免内存溢出。
    • 正则表达式优化，提高敏感信息检测效率。

故障排查

  • 无法分叉未保存的会话：
    • 如果会话尚未保存（没有 user/assistant 消息），分叉会报错。
  • 会话文件无效：
    • 空文件或非 pi 会话文件会被拒绝或初始化。
  • 会话头过大：
    • 超过扫描限制的会话头会抛出错误，用于保护系统。
  • 删除失败：
    • trash 不可用或失败时回退 unlink；若仍失败，检查权限与路径。
  • 分享失败：
    • Radius 未配置或认证失败；GitHub Gist 需要 gh auth login。
  • 新增 分享系统问题：
    • Token 无效：检查分享是否已过期或被撤销。
    • 权限错误：确认用户是否有访问权限。
    • 文件权限：检查 shares.json 文件权限是否为 0600。
  • 新增 交接文档问题：
    • 文档为空：检查会话是否有有效消息。
    • 敏感信息泄露：确认脱敏规则是否正确配置。
    • 生成失败：检查会话快照数据完整性。

最佳实践与迁移指南

  • 会话命名：
    • 使用 /name 或 --name 为会话设置可读名称，便于在 /resume 中识别。
  • 会话分组：
    • 默认按 cwd 分组存储；必要时使用 --session-dir 或 PI_CODING_AGENT_SESSION_DIR 调整存储位置。
  • 会话恢复策略：
    • 日常开发使用 --continue；跨项目或不确定时使用 --resume。
    • 明确指定会话时使用 --session，并根据提示决定是否 fork。
  • 会话分叉：
    • 使用 --fork 创建独立分支；如需固定 ID，结合 --session-id。
  • 会话清理：
    • 定期通过 /resume 删除无用会话；或直接删除对应 .jsonl。
  • 数据迁移：
    • 旧版本会话会在加载时自动迁移至最新版本。
    • 如需批量迁移，可复制 .jsonl 到新环境并重新加载。
  • 跨项目共享：
    • 使用 /export 或 /share 导出 JSONL/HTML 或分享链接。
    • 分享前审查敏感信息；必要时使用 Radius 组织可见性或 Gist 私有链接。
  • 新增 只读共享最佳实践：
    • 合理设置分享有效期，避免长期暴露敏感数据。
    • 定期检查并撤销不再使用的分享链接。
    • 使用 HTTPS 传输，确保分享链接安全。
    • 在生产环境中配置适当的文件权限。
  • 新增 交接文档使用指南：
    • 定期生成交接文档，便于团队协作。
    • 审查生成的文档，确保敏感信息已被正确脱敏。
    • 将文档保存到版本控制系统，便于追踪变更。
  • 新增 管理员操作规范：
    • 定期审查审计日志，监控异常操作。
    • 限制管理员账户数量，遵循最小权限原则。
    • 建立会话所有权转移流程，确保数据连续性。

结论

会话管理在本项目中由清晰的职责分层构成：CLI 参数驱动启动策略，启动装配确定 cwd 与服务，SessionManager 负责持久化与上下文构建，TUI 提供选择与操作体验，分享模块支持跨项目协作。新增的 Web API 层进一步增强了系统的功能性和安全性，提供了只读共享、交接文档生成和管理员控制等高级特性。通过 JSONL 与树结构，系统既能保留完整历史，又能高效构建模型上下文。配合新的分享系统和交接文档功能，可以在不同项目间安全、可控地创建、恢复、分叉、命名、删除、共享和交接会话，满足现代团队协作的需求。遵循本文的最佳实践，可以充分发挥会话管理系统的潜力，提升开发效率和协作质量。
