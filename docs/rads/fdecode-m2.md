## 1. 背景与价值

M1 已提供可日常使用的会话、流式对话、工具卡片、会话恢复、模型切换和用量统计。M2 补齐接近 TUI 的输入能力和多会话工作方式：

- 图片：把截图直接贴进对话。
- `@file`：引用项目文件，不必手动复制内容。
- 斜杠命令：发现并执行 prompt 模板、skills 和扩展命令。
- 会话分叉：从某条消息开新分支，不破坏原会话。
- 多会话并行：同时运行多个任务，切换时不丢状态。

这些能力都已在 Pi 的 CLI/TUI 或 RPC 协议中存在，M2 的工作是让 Web UI 正确暴露它们。

## 4. 使用场景

### 场景 1：贴截图排查问题

- 触发条件：用户截取报错或界面截图。
- 期望结果：粘贴到输入框，出现缩略图；发送后模型能看到图片；可移除或替换。

### 场景 2：引用项目文件

- 触发条件：输入 `@`，选择仓库内文件。
- 期望结果：文件内容按 CLI 语义进入 prompt；图片文件转为附件；结果可预览。

### 场景 3：执行斜杠命令

- 触发条件：输入 `/`。
- 期望结果：看到可用命令及描述；执行后按 Pi 的展开规则进入会话。

### 场景 4：从旧消息开分支

- 触发条件：用户想换一种方案，但保留原对话。
- 期望结果：从指定 user 消息 fork，新会话进入列表并自动打开；原会话不变。

### 场景 5：并行处理两个任务

- 触发条件：一个会话在跑长任务，用户想同时处理另一个问题。
- 期望结果：新会话独立运行；切回旧会话时状态和输出仍在。

## 6. 功能性需求

### 6.1 图片

- **IMG-1** 支持粘贴、拖拽和文件选择添加图片。
- **IMG-2** 发送前显示缩略图，可单个移除。
- **IMG-3** 按当前模型的图片输入能力和尺寸限制校验；超限时在客户端缩放或拒绝并说明原因。
- **IMG-4** 通过 `prompt.images` 发送 base64 图片；纯图片、图文混合都可发送。
- **IMG-5** 模型不支持图片时禁用附件入口并说明。

### 6.2 `@file`

- **FILE-1** 输入 `@` 打开文件候选列表，限定在当前项目目录内。
- **FILE-2** 支持键盘上下选择、Enter 确认、Esc 关闭。
- **FILE-3** 文本文件按 CLI 语义展开为 `<file name="绝对路径">内容</file>`。
- **FILE-4** 图片文件转为附件，并保留 `<file>` 提示，与 CLI 行为一致。
- **FILE-5** 跳过空文件；二进制或超大文件给出明确提示，不静默截断。
- **FILE-6** 候选搜索不进入 `.git`、`node_modules` 和大体积生成目录。

### 6.3 斜杠命令

- **CMD-1** 输入 `/` 显示 `get_commands` 返回的命令，含名称、描述和来源类型。
- **CMD-2** 选择后按 Pi 的规则执行：扩展命令、prompt 模板、`skill:` 命令。
- **CMD-3** 命令执行失败时显示错误，不把原始文本当普通 prompt 重发。
- **CMD-4** 支持键盘选择与 Esc 关闭。

### 6.4 会话分叉

- **FORK-1** 每条 user 消息提供“从这里分叉”操作。
- **FORK-2** 调用 `fork` 后把新会话加入列表并自动打开；原会话保留。
- **FORK-3** 提供 clone 当前分支的入口。
- **FORK-4** 新会话显示父会话或分叉来源，避免同名混淆。

### 6.5 多会话并行

- **PAR-1** 允许同时运行多个会话，默认上限 4，可通过环境变量调整。
- **PAR-2** 切换会话不中止原会话；后台会话继续接收事件。
- **PAR-3** 侧栏显示每个会话的 idle / streaming / error 状态。
- **PAR-4** 活跃会话超过上限时，明确提示并允许关闭空闲会话后重试。

## 7. 非功能约束

| 维度 | 约束 |
|---|---|
| 安全 | `@file` 只允许项目目录内路径；阻止 `..` 和符号链接逃逸；不提供任意文件下载 |
| 隐私 | 图片和文件内容只在本机传输；日志不记录正文 |
| 体积 | 单张图片压缩后不超过模型限制；单次 prompt 附件总量设上限（建议 20MB） |
| 性能 | 文件候选 200ms 内返回首批；并行 4 个会话时 UI 保持可交互 |
| 可维护 | 不新增 Pi 内核改动；`@file` 语义变化时以 CLI 源码为准并记录 |
| 兼容 | 现有 M1 会话、SSE 协议和运行时管理保持兼容 |

## 8. 开放问题

| 问题 | 影响 | 处理方式 |
|---|---|---|
| `@file` 展开是否需要复制 CLI 的图片处理与大小限制 | 行为一致性 | spike M2-S1 |
| fork / clone 后当前进程是否切换、新 session id 如何取得 | 分叉流程 | spike M2-S2 |
| 并行会话的事件连接策略：保持 SSE 还是按需快照 | 资源与实现复杂度 | spike M2-S3 |
| 图片压缩放浏览器还是服务端 | 依赖与画质 | spike M2-S4 |
| 斜杠命令的参数补全是否纳入 M2 | 范围 | 暂缓，先支持无参数执行 |
| 文件搜索是否遵循 `.gitignore` | 候选质量 | 先用固定排除目录，后续再评估 |

## 9. 用户故事（草案）

### US-M2-1 粘贴截图

- 作为用户，我要把截图直接贴进输入框，以便不保存文件也能让模型看图。
- 验收：粘贴后出现缩略图；发送后消息包含图片；可移除。

### US-M2-2 引用文件

- 作为用户，我要从项目里选择文件并按 CLI 语义带入，以便提供准确上下文。
- 验收：`@` 候选可用；文本按 `<file>` 包裹；图片转为附件。

### US-M2-3 执行命令

- 作为用户，我要看到并执行斜杠命令，以便复用模板和技能。
- 验收：命令列表含描述；执行结果与 TUI 一致。

### US-M2-4 从消息分叉

- 作为用户，我要从某条消息开新分支，以便保留原方案。
- 验收：新会话出现并打开；原会话消息不变。

### US-M2-5 并行会话

- 作为用户，我要同时运行两个任务，以便不被长任务阻塞。
- 验收：切换后原会话继续；侧栏状态正确。

## 10. 验收与成功指标

1. 截图粘贴、发送、移除全流程可用。
2. `@` 选择文本和图片文件，展开结果与 CLI 一致。
3. `/` 列表与执行可用，失败有提示。
4. 从 user 消息 fork 后新会话可继续对话，原会话不变。
5. 两个会话同时运行时，切换不丢事件，状态显示正确。
6. 现有 M1 功能不回归。
7. `pnpm run check` 与 `pnpm --filter @omfde/fdecode test` 通过。

成功指标：连续使用一周，图片、文件引用和分叉不需要回 TUI。
