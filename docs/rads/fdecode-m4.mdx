## 1. 背景与价值

M3 让 3~5 人团队可以共用一套服务：登录、工作区、用户归属和并发上限。但团队协作仍缺三件事：

- 一个人做完的会话，其他人看不到，也没有交接材料。
- 管理员无法查看团队整体会话分布。
- 关键操作没有审计记录。

M4 补齐“协作与交接”闭环，仍保持本地优先、单实例、3~5 人规模。

## 2. Vision 对齐

- 目标线：Web UI 线，并向平台化线的“协作层”供料。
- 当前阶段：团队可用之后的协作与交接。
- 对应 vision 条目：“线 3：FDE Code UI”“平台化线：协作层”。
- 边界判断：边界内；不引入多租户或企业级治理。

## 3. 干系人

| 角色 | 诉求 |
|---|---|
| 决策者 | 团队能交接工作，管理员能看全局 |
| 会话所有者 | 可控地分享只读结果 |
| 接手人 | 不追问原作者也能继续 |
| 维护者 | 审计与分享逻辑简单、可验证 |

## 4. 使用场景

### 场景 1：只读分享

- 所有者把一个会话分享给团队。
- 其他人通过链接打开，只能查看，不能发送命令。
- 所有者可以随时撤销。

### 场景 2：交接文档

- 会话结束时，所有者导出交接材料。
- 文档包含目标、改动、命令、未完成事项和风险。
- 接手人按文档继续，不需要重新读完整 transcript。

### 场景 3：管理员查看

- 管理员查看所有用户的会话列表和工作区分布。
- 默认只读，不能代替所有者操作。

### 场景 4：审计

- 登录、创建会话、分叉、克隆、分享、删除都有记录。
- 管理员可以查看最近事件，用于排查误操作。

## 5. 范围与非目标

### 本期范围

- 会话只读分享与撤销。
- 交接文档导出（Markdown）。
- 管理员角色与全局会话列表。
- 本地追加式审计日志与管理员查询。

### 非目标

- 实时协作、评论、在线状态。
- 细粒度 RBAC、组织架构。
- 未登录的外部分享链接。
- 审计数据库、长期归档、合规报表。
- 会话内容自动脱敏。

### 涉及区域（初判）

- [x] `apps/fdecode/`
- [x] `docs/`
- [ ] `packages/`（预计不改）

## 6. 功能性需求

### 6.1 分享

- **SHARE-1** 所有者可以为会话创建只读分享链接。
- **SHARE-2** 分享链接包含随机 token，可设置过期时间（默认 7 天）。
- **SHARE-3** 访问分享链接必须已登录；非团队成员不可见。
- **SHARE-4** 分享视图只读：不能发送命令、中止、重命名、分叉或删除。
- **SHARE-5** 所有者可以列出并撤销分享。
- **SHARE-6** 撤销后链接立即失效，已打开的只读视图下次刷新不可用。

### 6.2 交接文档

- **HANDOFF-1** 从当前会话生成 Markdown 交接文档。
- **HANDOFF-2** 内容至少包含：工作区、模型、用户请求、助手结论、工具调用摘要、未完成事项和风险。
- **HANDOFF-3** 文档由用户主动下载，不在服务端长期保存。
- **HANDOFF-4** 不包含 API key、配置密钥或环境变量值。

### 6.3 管理员

- **ADMIN-1** 用户配置支持 `role: "admin"`，默认 `member`。
- **ADMIN-2** 管理员可以查看所有用户的会话列表，包含 owner、工作区、时间和消息数。
- **ADMIN-3** 管理员默认只读；要操作会话仍需所有者授权或转移归属。
- **ADMIN-4** 普通成员看不到管理员接口。

### 6.4 审计

- **AUDIT-1** 记录登录成功/失败、会话创建、分叉、克隆、分享创建/撤销、会话删除。
- **AUDIT-2** 每条记录包含时间、用户、动作、目标 id 和结果。
- **AUDIT-3** 审计日志追加写入 `~/.fdecode/audit.jsonl`，权限 0600。
- **AUDIT-4** 管理员可以查询最近 N 条记录。
- **AUDIT-5** 不记录 prompt、工具输出或文件内容。

## 7. 非功能约束

| 维度 | 约束 |
|---|---|
| 安全 | 分享 token 至少 128 位随机；撤销即时生效；只读接口不接受写命令 |
| 隐私 | 审计只记元数据；交接文档由用户触发 |
| 性能 | 1000 条审计记录查询 < 200ms |
| 兼容 | M1–M3 行为不变；成员默认不感知管理员能力 |
| 可维护 | 复用现有 owner 索引和配置，不引入数据库 |

## 8. 开放问题

| 问题 | 影响 | 处理方式 |
|---|---|---|
| 分享链接是否允许未登录访问 | 安全边界 | spike M4-S1，建议必须登录 |
| 分享 token 存哪里、如何撤销 | 实现 | spike M4-S1 |
| 交接文档能从哪些数据生成 | 文档质量 | spike M4-S2 |
| 审计日志并发追加如何保证 | 可靠性 | spike M4-S3 |
| 管理员是否需要会话操作权 | 权限 | 默认只读，后续再议 |

## 9. 用户故事（草案）

### US-M4-1 分享会话

- 作为所有者，我要把会话以只读方式分享，以便同事查看结果。
- 验收：创建链接、打开只读、撤销后失效。

### US-M4-2 导出交接

- 作为所有者，我要下载交接文档，以便别人继续任务。
- 验收：文档包含目标、改动、工具摘要、风险和下一步。

### US-M4-3 管理员查看

- 作为管理员，我要查看全部会话，以便了解团队进展。
- 验收：能看到所有 owner 与工作区；不能直接操作。

### US-M4-4 查看审计

- 作为管理员，我要查看最近操作，以便排查误删或异常登录。
- 验收：事件包含时间、用户、动作、目标、结果。

## 10. 验收与成功指标

1. 分享链接只读，撤销后访问失败。
2. 交接文档可独立阅读，包含未完成事项与风险。
3. 管理员能看到全部会话，普通成员不能。
4. 审计记录覆盖约定动作，不含正文。
5. M1–M3 功能不回归；`pnpm run check` 与 app 测试通过。

成功指标：一次交接不需要原作者在线解释。

## 11. 风险与依赖

| 类型 | 内容 | 应对 |
|---|---|---|
| 风险 | 分享 token 泄漏 | 随机 token、过期、撤销、必须登录 |
| 风险 | 只读接口被绕过 | 独立只读路由与命令端点分离 |
| 风险 | 审计日志被篡改 | 0600、追加写、管理员只读查询 |
| 风险 | 交接文档泄漏敏感信息 | 只取消息与工具摘要，不导出环境变量 |
| 依赖 | 现有 owner 索引 | 复用并扩展角色字段 |
