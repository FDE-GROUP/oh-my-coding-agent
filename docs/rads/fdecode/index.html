RAD：FDE Code UI

效力：经决策者确认后，本文件 = 确认需求，是后续 spike、实现计划和验收的依据；实现计划另行编写。

流程：vision → RAD → spike → plan → 实现，详见 docs/specs/workflow.md。

状态 已确认

关联 milestone FDE Code UI M1

1. 背景与价值

Pi 目前只有 TUI 和 RPC/SDK 两种使用方式。TUI 适合个人终端，但不便于演示、远程查看和团队统一体验；SDK 面向开发者，不提供现成界面。

本项目需要一个独立的 FDE Code UI：在浏览器里完成一次完整的 Pi 会话，包括对话、工具调用、中止、模型切换和会话恢复。它同时是 DSH 设计系统的一次落地实践：布局、token 分层和共享控件复用方式对齐 DSH，但不复制 DSH 的包数量与插件架构。

价值：

  • 降低使用门槛：不需要配置终端也能用 Pi。
  • 改善长会话体验：工具输出、thinking、diff 更易读。
  • 为团队统一界面打基础：后续平台界面可以复用同一套布局和设计系统。
  • 验证 RPC 协议是否足以支撑一个完整客户端，为后续扩展提供证据。

关联文档：

  • docs/specs/vision.md“线 3：FDE Code UI”
  • packages/coding-agent/docs/rpc.md
  • packages/coding-agent/docs/rpc-commands.md
  • packages/coding-agent/docs/json.md
  • packages/coding-agent/docs/rpc-extension-ui.md

2. Vision 对齐

  • 目标线：Web UI 线（第三条目标线）
  • 当前阶段：线 3 第一阶段“可用界面”，并开始对齐 DSH
  • 对应 vision 条目：“线 3：FDE Code UI”“布局、设计系统与样式实现”“前端技术栈”
  • 边界判断：边界内。独立应用、本地单用户、不改 Pi 内核，均符合 vision。
  • 若冲突：无。

3. 干系人

角色 诉求
决策者（Abel） 能连续几天用它代替 TUI 干活；界面可信、状态不丢
首个用户（Abel） 长会话可读、工具结果清楚、中止及时
团队用户（M2 起） 同一套界面和习惯，不依赖个人终端配置
维护者 只依赖 RPC 协议和公开导出；Pi 升级时改动面可控

4. 使用场景

场景 1：日常任务

  • 触发条件：有一个需要读代码、跑命令、改文件的任务。
  • 参与者：用户、Pi。
  • 期望结果：在浏览器里输入任务，实时看到回复和工具调用，结束后结果完整可读。

场景 2：工具跑偏时介入

  • 触发条件：工具执行方向不对，或输出明显错误。
  • 参与者：用户、Pi。
  • 期望结果：能中止当前运行；需要时追加 steering 指令，不必重开会话。

场景 3：离开再回来

  • 触发条件：会话运行中关闭浏览器，或网络中断。
  • 参与者：用户、Pi。
  • 期望结果：Pi 继续运行；重新打开页面后看到完整历史和最终结果。

场景 4：恢复旧会话

  • 触发条件：第二天继续昨天的任务。
  • 参与者：用户、Pi。
  • 期望结果：从会话列表恢复，历史、模型、token 和费用状态正确。

5. 范围与非目标

本期范围（M1）

一个本地启动、可日常使用的 Web UI：

  1. 会话：新建、列表、恢复、重命名。
  2. 对话：prompt、流式文本、thinking、工具调用与结果、中止、steering / follow-up 排队。
  3. 控制：模型切换、token 与费用、运行状态。
  4. 布局：三栏 AppFrame、响应式侧栏、主题（light/dark/system）。
  5. 接入：RPC 子进程、SSE 事件流、断线重连。

已确认的形态决策

决策 结论
应用位置 apps/fdecode 独立 package；不依赖 apps/omfde，不并入平台
接入方式 RPC 子进程（pi --mode rpc）
事件传输 SSE + POST
进程模型 一会话一进程；空闲 30 分钟回收，会话文件保留
断连行为 Pi 继续运行；重连拉取状态与消息后继续
M1 会话列表 包含；会话索引来自公开导出的 SessionManager，不读内部实现
M1 扩展 UI 只处理 notify 和“取消”响应；完整交互推迟到 M2

非目标

  • 多用户、登录、权限、审计。
  • 远程部署、公网访问。
  • 文件编辑器、终端模拟器、Git 图形操作。
  • 插件市场、主题市场。
  • 移动端原生应用。
  • 自建会话存储；会话事实仍归 Pi。
  • 改 Pi 内核；只使用 RPC 协议与公开导出。

涉及区域（初判）

  • apps/fdecode/（新增）
  • packages/（只读引用公开导出）
  • extensions/
  • docs/rads/、docs/plans/、docs/spikes/

6. 功能性需求

6.1 会话生命周期

  • FR-1 启动后自动打开最近会话或新建空会话，不出现空白路由。
  • FR-2 新建会话；旧会话保留在 Pi 的 session 目录。
  • FR-3 会话列表展示名称、时间、工作目录、消息数；按修改时间倒序。
  • FR-4 恢复会话时加载完整历史，包括工具调用与结果。
  • FR-5 会话重命名，写回 Pi 的 session 信息。

6.2 对话流

  • FR-6 发送 prompt；流式渲染文本，增量追加，结束时以 message_end 校正。
  • FR-7 thinking 独立区块，默认折叠，可展开。
  • FR-8 流式中可继续输入，按 steer / followUp 两种语义排队，并显示待发送队列。
  • FR-9 中止当前运行；中止后状态明确，不残留“正在输入”。
  • FR-10 错误可见：provider 失败、工具失败、扩展异常分别呈现，不吞掉。

6.3 工具调用

  • FR-11 工具调用卡片展示工具名、参数、状态、耗时。
  • FR-12 工具结果至少支持文本、代码、diff 三种呈现；超长输出折叠可展开。
  • FR-13 工具执行中的部分输出可见（tool_execution_update）。
  • FR-14 工具调用与结果按 toolCallId 配对，乱序到达不错位。

6.4 控制与状态

  • FR-15 模型切换；候选来自 get_available_models，对下一次请求生效。
  • FR-16 展示 token 用量、费用、上下文占用百分比。
  • FR-17 展示运行状态：idle / streaming / compacting / retrying，以后端事件为准。
  • FR-18 扩展弹窗请求在 M1 至少能取消，不能把 agent 挂死；notify 显示为提示。

6.5 布局、主题与样式

  • FR-19 三栏 AppFrame：左侧栏、中间会话、右侧面板位；右侧在 M1 可空置但结构存在。
  • FR-20 左侧栏宽度 264–420px，默认 280px；≥768px 折叠为 56px rail；<768px 改为抽屉；<1024px 自动收起。
  • FR-21 主题 light / dark / system，跟随系统变化；选择持久化。
  • FR-22 设计 token 与 DSH 对齐：颜色、圆角、阴影、焦点环、滚动条走主题层，组件不写死。
  • FR-23 字体角色分离：正文、代码；字号可调。

6.6 推迟到 M2

  • 图片粘贴（RPC 已支持 prompt.images）。
  • @file 引用（RPC 拒绝 @file 参数，需要后端展开）。
  • 斜杠命令与 skills 列表（get_commands）。
  • 会话分叉、克隆、分支树（fork、clone、get_tree）。
  • compaction 交互与摘要展示。
  • 扩展完整 UI（select / confirm / input / editor / widget）。
  • 多会话并行标签页。
  • 会话导出 HTML。

7. 非功能约束

维度 约束
安全 只绑定 127.0.0.1；校验 Origin 与 Host，防 DNS rebinding 和跨站请求；浏览器不接触文件系统与密钥
隔离 Pi 跑在子进程；Web 后端崩溃不丢会话；Pi 崩溃时界面明确报错并可重启
一致性 会话事实以 Pi 为准：get_state + get_messages 是恢复来源，前端状态可丢弃
重连 事件不可重放；重连必须重新拉取状态与消息，再继续接收
性能 本地流式首字节 < 500ms；一万条消息的会话可滚动不卡死
兼容 当前 Chromium / Firefox / Safari 最近两个大版本
可维护 不 import Pi 内部实现；只依赖 RPC 协议文档与公开导出
隐私 不引入遥测；日志默认不记录 prompt 内容
技术栈 React + TanStack Start + Tailwind CSS + Vite；样式规范见 vision“前端技术栈”

8. 开放问题

问题 影响 处理方式
TanStack Start 用哪个版本，目录约定如何落地 脚手架与路由结构 plan 中锁定
--dsw-* token 如何映射到 Tailwind theme 主题层实现方式 plan 中给出映射表
会话列表如何区分“当前项目”与“全部项目” 恢复体验与性能 M1 默认当前项目，全部项目放 M2
空闲回收后，重连需要重启进程的等待时间 恢复体验 plan 中定义加载态与超时
@file 展开语义与 CLI 不一致 M2 功能范围 M2 前 spike
多会话并行时后端进程上限 资源占用 M2 决定

9. 用户故事

US-1 新建并开始任务

  • 作为用户，我要打开页面就能新建会话并输入任务，以便不配置终端也能使用 Pi。
  • 验收条件：
    • Given 后端已启动，When 打开首页，Then 自动进入一个可用会话。
    • When 发送 prompt，Then 文本开始流式出现。
  • 对应：FR-1、FR-6

US-2 看清工具执行

  • 作为用户，我要看到工具名、参数、输出和耗时，以便判断 Pi 做了什么。
  • 验收条件：
    • Given 一次含工具调用的运行，When 工具开始执行，Then 出现对应卡片并显示状态。
    • When 工具结束，Then 结果按类型呈现，调用与结果不错位。
  • 对应：FR-11、FR-12、FR-14

US-3 及时中止

  • 作为用户，我要在中止运行后立即得到明确状态，以便纠正方向。
  • 验收条件：
    • Given 正在流式输出，When 点击中止，Then 一秒内停止并回到 idle。
    • Then 不残留“正在输入”状态。
  • 对应：FR-9

US-4 流式中追加指令

  • 作为用户，我要在运行中追加 steering 或 follow-up，以便不重开会话就能调整任务。
  • 验收条件：
    • Given 正在运行，When 提交 steering，Then 消息进入待发送队列并在合适时机送达。
    • When 提交 follow-up，Then 在当前工作结束后送达。
  • 对应：FR-8

US-5 离开再回来

  • 作为用户，我要在关闭浏览器后仍保留会话，以便长任务不中断。
  • 验收条件：
    • Given 运行中，When 关闭浏览器再打开，Then Pi 仍在运行或已完成，历史完整。
    • Then 界面状态与 Pi 的 get_state 一致。
  • 对应：FR-4、FR-17

US-6 恢复旧会话

  • 作为用户，我要从列表恢复昨天的会话，以便继续工作。
  • 验收条件：
    • Given 已有多个会话，When 打开列表，Then 按修改时间倒序显示名称、时间、目录。
    • When 选择一个会话，Then 历史、模型、token 与费用正确。
  • 对应：FR-3、FR-4、FR-15、FR-16

US-7 切换模型

  • 作为用户，我要切换模型，以便按任务选择成本或能力。
  • 验收条件：
    • Given 已加载模型列表，When 选择另一个模型，Then 下一次请求使用新模型。
  • 对应：FR-15

US-8 主题与布局

  • 作为用户，我要界面跟随系统主题并适配窗口宽度，以便长时间使用。
  • 验收条件：
    • Given 系统为深色，When 打开页面，Then 使用深色主题；切换系统主题后跟随。
    • Given 窗口宽度 1200 / 900 / 600px，Then 分别呈现三栏、收起侧栏、抽屉。
  • 对应：FR-19、FR-20、FR-21、FR-22

10. 验收与成功指标

验收步骤

  1. 一条命令启动，浏览器打开 127.0.0.1 即可用。
  2. 发一条带工具调用的任务：文本、thinking、工具卡片、结果均正确且顺序稳定。
  3. 运行中点中止：1 秒内停止，界面回到 idle。
  4. 运行中刷新页面：会话继续，回来后历史完整。
  5. 切换模型后，下一次请求使用新模型。
  6. 恢复旧会话：历史、费用、token 正确。
  7. 宽度 1200 / 900 / 600px 下布局分别表现为三栏、收起侧栏、抽屉。
  8. 主题跟随系统切换，刷新后保持。
  9. 浏览器开发者工具中看不到 API key，也没有任意文件读取接口。

成功指标

  • 连续 3 个工作日用 Web UI 完成真实任务，不需要回退 TUI。
  • 会话恢复和断线重连不丢消息。
  • Pi 崩溃时界面能说明原因并允许重启会话。

失败判定

  • 需要频繁刷新才能看到状态。
  • 工具结果与调用错位。
  • 断连后会话丢失或出现两份历史。

11. 风险与依赖

类型 内容 应对
依赖 Pi RPC 协议 只依赖文档记录的记录类型；协议变化时先更新文档再改客户端
依赖 SessionManager 公开导出 只用导出的列表与信息字段，不读 session 文件内部结构
风险 事件不可重放导致恢复复杂 重连固定走状态 + 消息拉取，不做增量假设
风险 扩展弹窗阻塞 agent 未处理请求统一回 cancelled
风险 单进程多数会话造成资源占用 M1 限制同时活跃会话数，空闲回收
风险 Tailwind 与 DSH token 映射失真 plan 中先做 token 映射表，再做最小页面
