## 1. 背景与价值

M1–M4 已覆盖会话、团队访问、分享、交接和审计。团队日常仍需要：

- 从 GitHub Issue 直接开始任务，而不是手工复制需求。
- 在界面里看到关联分支的 CI 状态。
- 长任务结束时收到通知，不必盯着页面。
- 控制会话和审计数据的保留周期，避免磁盘无限增长。

M5 把这些外部系统和运维能力接入，但保持本地单实例、3~5 人规模。

## 2. Vision 对齐

- 目标线：Web UI 线，向平台化线的“企业集成”供料。
- 当前阶段：团队可用之后的集成与运维。
- 对应 vision 条目：“线 3：FDE Code UI”“平台化线：企业集成”。
- 边界判断：边界内；不引入多租户或企业级权限体系。

## 3. 干系人

| 角色 | 诉求 |
|---|---|

| 维护者 | token 不进浏览器、清理可回滚、失败可诊断 |

## 4. 使用场景

### 场景 1：从 Issue 开始任务

- 用户在侧栏选择仓库和 open issue。
- 创建会话时自动带入 issue 标题、正文和链接作为上下文。
- 会话可以记录关联的 issue。

### 场景 2：查看 CI 状态

- 会话关联仓库后，顶部显示最近一次 workflow run 的状态。
- 点击打开 GitHub run 页面；失败时显示分支和结论。

### 场景 3：任务完成通知

- 长任务结束时，如果页面在后台，发送浏览器通知。
- 页面内保留未读通知列表。

### 场景 4：保留策略

- 管理员配置会话、审计、分享的保留天数或数量。
- 清理前可以 dry-run 查看将删除的内容。
- 活跃会话和未过期分享不会被删除。

## 5. 范围与非目标

### 本期范围

- GitHub 仓库配置与 token。
- open issue 列表、issue 关联会话、issue 上下文注入。
- 最近 CI run 状态展示。
- 页面内通知 + 可选浏览器通知。
- 会话、审计、分享的保留策略与手动清理。

- 邮件、Slack、Webhook 通知。

- 自动删除正在运行的会话。

## 6. 功能性需求

### 6.1 GitHub 与 Issue

- **GH-1** 配置支持一个或多个仓库（`owner/repo`）与可选 token。
- **GH-2** token 只从配置或环境读取，不返回浏览器、不写日志。
- **GH-3** 侧栏可以查看配置仓库的 open issues（标题、编号、标签、更新时间）。
- **GH-4** 创建会话时可以把 issue 作为上下文：标题、正文、链接进入首条 prompt。
- **GH-5** 会话记录关联的 issue，列表和详情可见。
- **GH-6** API 失败时显示明确错误，不阻塞普通会话。

### 6.2 CI 状态

- **CI-1** 展示关联仓库/分支最近一次 workflow run 的状态、结论和时间。
- **CI-2** 支持手动刷新；自动刷新间隔不短于 60 秒。
- **CI-3** 状态包含 queued、in_progress、success、failure、cancelled 等。
- **CI-4** 点击状态打开 GitHub run 页面。
- **CI-5** 未配置仓库或 token 时隐藏入口，不报错。

### 6.3 通知

- **NOTIF-1** 页面内通知列表，记录会话结束、失败、分享/清理等重要事件。
- **NOTIF-2** 浏览器通知需用户显式授权，默认关闭。
- **NOTIF-3** 页面隐藏时，会话 settled 或 error 可触发浏览器通知。
- **NOTIF-4** 通知支持已读/全部已读，未读数显示在标题栏。
- **NOTIF-5** 不向浏览器通知发送 prompt 或工具输出正文。

### 6.4 保留策略

- **RET-1** 配置支持会话、审计、分享的保留天数；0 表示不自动清理。
- **RET-2** 提供手动清理入口和 dry-run 预览。
- **RET-3** 清理对象包括会话文件、owner 索引、分享记录；审计只清理旧记录。
- **RET-4** 活跃会话、未过期分享、当前会话不会被删除。
- **RET-5** 清理动作写入审计，记录数量和范围，不记录正文。
- **RET-6** 清理失败时停止并报告，不静默部分删除。

## 7. 非功能约束

| 维度 | 约束 |
|---|---|
| 安全 | GitHub token 不返回浏览器；API 请求由服务端代理；日志脱敏 |
| 网络 | GitHub 请求超时 10 秒；失败不影响会话；支持离线 |
| 性能 | issue 列表最多 50 条；CI 状态缓存 60 秒 |
| 数据 | 清理前必须 dry-run；删除不可逆，需二次确认 |
| 兼容 | 未配置 GitHub / 保留策略时行为与 M4 一致 |
| 可维护 | 不引入数据库；沿用 JSON 配置与文件存储 |

## 9. 用户故事（草案）

### US-M5-1 从 Issue 开始

- 作为用户，我要从 open issue 创建会话，以便直接带着需求上下文开始。
- 验收：会话首条消息包含 issue 标题、正文和链接；列表显示关联 issue。

### US-M5-2 查看 CI

- 作为用户，我要看到关联分支的 CI 状态，以便知道改动是否通过。
- 验收：状态、结论、时间可见；点击打开 run 页面。

### US-M5-3 任务通知

- 作为用户，我要在长任务结束时收到通知，以便不必盯着页面。
- 验收：页面隐藏时会话结束触发通知；页面内未读数正确。

### US-M5-4 清理旧数据

- 作为管理员，我要按保留策略清理旧会话和审计，以便控制磁盘。
- 验收：dry-run 列出对象；确认后删除；活跃会话不受影响；审计有记录。

## 10. 验收与成功指标

1. 未配置 GitHub 时 M1–M4 行为不变。
2. issue 列表与上下文注入可用；token 不出现在浏览器响应或日志。
3. CI 状态展示与链接可用；失败有明确提示。
4. 通知可开关；页面隐藏时能收到；未读数正确。
5. dry-run 与清理可用；活跃会话和未过期分享不被删除；审计记录完整。
6. `pnpm run check` 与 app 测试通过。

成功指标：一周内团队从 Issue 创建会话 ≥ 5 次；清理后磁盘占用可预测。

## 11. 风险与依赖

| 类型 | 内容 | 应对 |
|---|---|---|
| 依赖 | GitHub API 可用性与限流 | 超时、缓存、错误提示 |
