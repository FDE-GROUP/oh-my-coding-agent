## 1. 背景与目标

M1 已交付会话、流式对话、工具卡片、恢复、模型与用量。M2 补齐输入能力和多会话工作方式：图片、`@file`、斜杠命令、会话分叉、多会话并行。

目标：日常使用时不需要回 TUI 完成这些操作，且不破坏 M1 行为。

## 2. 非目标

- 不改 Pi 内核。
- 不做文件编辑器、完整文件浏览器、图片编辑。
- 不做命令参数补全、技能市场、远程访问、多用户。
- 不实现跨项目搜索或会话合并。

## 3. 设计要点

### 3.1 `@file`

新增 `src/server/files.ts`：

- `searchFiles(query, limit)`：从项目目录递归搜索，排除 `.git`、`node_modules`、`dist`、`.tanstack`、`.next`、`coverage`；返回相对路径。
- `expandFiles(paths)`：校验路径在项目目录内（`realpath` 后仍以项目目录开头），然后：
  - 空文件跳过；
  - 图片按 MIME 检测，读为 base64 附件，文本部分写 `<file name="绝对路径"></file>`；
  - 文本文件按 CLI 格式包裹：`<file name="绝对路径">\n内容\n</file>\n`，剥离 BOM；
  - 二进制（含 NUL）拒绝；
  - 文本上限 256KB，图片上限 10MB。
- 不生成图片尺寸 hints；Pi 会在 prompt 阶段按模型限制规范化图片。

API：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/files/search?q=` | 返回相对路径候选，最多 100 条 |
| POST | `/api/files/expand` | `{ paths: string[] }` → `{ text, images }` |

前端：输入 `@` 打开候选浮层，键盘上下选择，Enter 插入；选中后调用 expand，把文本追加到草稿，图片放入附件列表。

### 3.2 图片

- Composer 支持粘贴、拖拽、文件选择。
- 浏览器用 canvas 预缩放：长边最多 2048px，单图不超过 5MB；超出时压缩后加入。
- 附件列表显示缩略图、大小、移除按钮。
- 发送时把图片放进 `prompt.images`；模型 `input` 不含 `image` 时禁用附件入口。
- Pi 仍会按 `inputLimits.images.resize` 做最终规范化（spike 已确认）。

### 3.3 斜杠命令

- 会话加载后调用 `get_commands`，缓存到当前会话状态。
- 输入 `/` 打开命令浮层，显示名称、描述与来源类型。
- 选择后把 `/name` 放入草稿或直接执行；执行仍走 `prompt`，由 Pi 展开。
- 失败显示错误，不回退成普通文本。

### 3.4 分叉

API：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/sessions/:id/fork` | `{ entryId }`，返回新 session id |
| POST | `/api/sessions/:id/clone` | 返回新 session id |

服务端流程：

1. 执行 `fork` / `clone` 命令。
2. `get_state` 读取新的 session id 和文件。
3. 从运行时映射中删除旧 id，把同一个 runtime 注册到新 id。
4. 返回 `{ id, state }`。

前端：

- 执行后刷新会话列表并跳转新 id。
- user 消息悬浮菜单提供“从这里分叉”。
- 会话标题栏提供“克隆当前分支”。
- 列表显示父会话信息（有 `parentSessionPath` 时）。

### 3.5 多会话并行

- 只为当前会话建立 SSE；后台会话由服务端继续运行。
- 新增 `GET /api/runtimes`：返回活跃 session id、busy、最后活动时间。
- 侧栏每 2 秒轮询一次，显示 idle / streaming / error。
- 保留默认 4 个活跃运行时；有空闲时自动回收最久未活动的运行时，全部忙碌时返回 429 并在 UI 提示。
- 切换会话时复用 `resumeSession`；若运行时已被回收，会重新启动并从会话文件恢复。

### 3.6 否决项

| 选项 | 理由 |
|---|---|
| CLI `@file` 参数 | RPC 拒绝 |
| 服务端图片缩放 | `processImage` 未公开导出，Pi 已处理 |
| 每会话常驻 SSE | 连接成本高，快照足够 |
| 直接改 session 文件分叉 | 用 RPC，避免格式漂移 |
| 超限一律 429 | 空闲回收更符合使用习惯 |

## 6. 风险

| 风险 | 应对 |
|---|---|
| 路径逃逸 | `realpath` 前缀校验，拒绝符号链接逃逸 |
| 大请求 | 浏览器预缩放 + 服务端大小上限 |
| fork 后路由错位 | 服务端返回新 id，前端强制跳转 |
| 并行内存 | 4 个上限、空闲回收、状态提示 |
| 命令与模板行为差异 | 只透传 `/name`，由 Pi 展开 |
