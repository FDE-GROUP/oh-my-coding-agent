模块按「数据 + 代码」两层组织：
- `data/*.json` 由外部 catalog 生成器产出，每个文件描述一个 provider 的 chat/image/classifier 模型元数据；`.manifest.json` 维护 schemaVersion / generatedAt / files SHA 以校验完整性。
- `*.models.ts` 是自动生成层（注释声明 `auto-generated by catalog/generate.ts`），通过 `flattenChatModelCatalog`/`flattenImageModelCatalog`/`flattenClassifierModelCatalog` 把 JSON 转为类型安全的 `*MODELS` 常量。
- `*.ts` 是运行时 provider 工厂，调用 `createProvider` 装配 id/name/baseUrl/auth/models/api/classifiers，并把对应 `.models.ts` 导出的模型表注入 `models` 字段；`all.ts` 集中 import 并导出 `builtinProviders()`、`getBuiltinModel(s)`、`builtinModels()` 作为统一入口。
- 特殊分支：`radius.ts` 不依赖静态模型表，而是通过 `radius-config.ts` 动态拉取网关目录并持久化到 `context.stored`；`faux.ts` 提供纯内存模拟 Provider 供测试使用；`images/register-builtins.ts` 懒加载 image API 并通过 `registerImagesApiProvider` 注册到全局 registry。
- 共享建模规范集中在 `model-schema.ts`（thinkingLevelMap、costRates、inputLimits、promptCache 等 schema 定义）和 `schema-builders.ts`，被各 provider 的 models 文件复用。
- 依赖方向单向：providers → `../api/*`（lazy 导入）、`../auth/*`、`../models.ts`、`../types.ts`，不反向引用上层应用。
