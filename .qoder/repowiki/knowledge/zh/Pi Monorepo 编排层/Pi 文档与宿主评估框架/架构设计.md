模块按职责拆分为四层：
- `src/harness.ts`：核心运行时，封装 `vitest-evals/harness` 的 `createHarness`，通过 `@earendil-works/pi-coding-agent` 创建隔离的 `AgentSession`，支持可选的 `output` 转换器、系统提示词注入/校验、以及基于 POSIX uid/gid 的工具沙箱（`enterToolSandbox`）。
- `src/docker.ts`：容器编排层，构建两个 Docker 目标（`with_docs` / `without_docs`），以只读根文件系统 + tmpfs + 非 root 用户（65532:65532）运行 eval，并通过 `discoverCases` / `runTask` 驱动 Vitest 项目 `docs`。
- `src/plan.ts`：任务规划，将发现的用例扩展为每个变体 × runsPerVariant 的 `EvalTask`，并强制要求用例名形如 `<eval set> > <case>`。
- `src/report.ts`：结果聚合，读取 `@vitest-evals/core` 产出的 JSON 报告，配对 control/treatment 计算通过率提升、token/tool/latency/cost 均值差，并持久化 session JSONL 快照。
- `src/cli.ts`：顶层入口，解析 `--provider/--model/--runs-per-variant` 等参数，生成 `protocol.json` + `expected-runs.json`，串行执行任务并输出 `report.json` / `report.txt`。
- `evals/*.docs.eval.ts` 与 `evals/*.eval.ts`：实际评估用例；前者走 Docker 双变体对比，后者在宿主机 fork 池单进程执行。
- `docker/Dockerfile` + `entrypoint.ts` + `install-runtime.mjs`：容器镜像定义与启动脚本。
依赖方向单向：cli → docker/plan/report → harness → pi-coding-agent；测试位于 `test/`，使用独立的 `vitest.test.config.ts`。
