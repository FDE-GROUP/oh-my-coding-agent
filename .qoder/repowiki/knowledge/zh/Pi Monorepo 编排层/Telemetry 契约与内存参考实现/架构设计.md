模块以 `src/index.ts` 暴露核心契约（`TelemetryContext`、`TelemetrySpan`、`TelemetryStore`、`TelemetryPropagation`、`StoredSpan`/`StoredMetric` 等），并通过 `defineTelemetrySchema` + 大量条件类型在编译期从 schema 推导 span 名称、start/end/event 属性及度量仪器接口；`src/metrics.ts` 在此基础上导出 `createTypedMetrics`，将运行时 instrument 名称绑定到 schema 定义。

- `src/memory.ts`：`InMemoryTelemetryContext` 同时实现 `TelemetryContext` / `TelemetryPropagation` / `TelemetryMetrics` / `TelemetryStore`，用内部 `MutableRecordedTelemetrySpan` 树记录 span，通过 `pi-memory-scope/span/trace` 键作为 carrier 进行跨进程传播，并提供 `telemetryNow()` 把 `performance.now()` 锚定到 `Date.now()` 产生微秒级毫秒时间戳。
- `src/noop.ts`：共享冻结的 `NOOP_TELEMETRY_CONTEXT` / `NOOP_TELEMETRY_METRICS` / `NOOP_TELEMETRY_PROPAGATION`，用于无观测场景。
- `src/render.ts`：纯函数 `renderTrace`，把 `StoredSpan[]` 渲染为带缩进、事件、link 和错误信息的文本森林，并对控制字符做转义。
- `src/testing/`：面向测试的 `Conformance` 基类与 `types.ts`，供下游 adapter 复用同一份行为断言。

依赖方向单向收敛：`memory` → `noop` → `index`；`metrics` → `index`；`render` → `index`；`testing` 仅依赖契约类型。包通过 `package.json` 的 `exports` 字段分别暴露 `.`、`./render`、`./testing` 三个入口，构建产物位于 `dist/`，由 `tsc -p tsconfig.build.json` 产出。
