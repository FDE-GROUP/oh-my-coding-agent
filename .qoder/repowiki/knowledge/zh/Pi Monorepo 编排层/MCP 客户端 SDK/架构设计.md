模块按职责分层组织：
- `src/client.ts` 中的 `McpClient` 是核心状态机（idle/connecting/connected/closed），负责 initialize 握手、请求-响应匹配、进度回调、取消与超时、服务器端请求分发。
- `src/transports/` 实现 `McpTransport` 接口（`start/send/close/onMessage/onError/onClose`），通过抽象基类 `TransportEvents` 统一事件派发；具体实现包括 `stdio.ts`（子进程 stdin/stdout）、`pipe.ts`（Node Pipe）、`streamable-http.ts`（HTTP + OAuth）和 `in-memory.ts`（测试用）。
- `src/protocol/` 定义 JSON-RPC 2.0 消息类型与解析器，`content.ts` 定义 MCP 内容块（text/image/audio/blob/resource-link），`types.ts` 暴露 MCP 协议常量与能力描述。
- `src/oauth/` 是独立子包，封装 RFC 8414 / OIDC Discovery / Client ID Metadata Documents / DCR 等流程，提供 `authorizeMcp`、`refreshAuthorization`、`startMcpSignIn`、`OAuthCallbackServer` 及 loopback 回调监听。
- 辅助层：`config.ts` 校验 `mcpServers` 配置（stdio/http 两种 server 形态），`input-schema.ts` 规范化工具输入 schema，`naming.ts` 生成 MCP 工具名与命名空间，`output-limit.ts` 限制输出字节数。
- 对外通过 `package.json` 的 `exports` 字段暴露三个入口：`@earendil-works/pi-mcp`（主 API）、`./oauth`、`./testing`，所有内部类型由 `src/index.ts` 统一 re-export。依赖方向单向：client → transports/protocol，oauth 独立不反向依赖 client。
