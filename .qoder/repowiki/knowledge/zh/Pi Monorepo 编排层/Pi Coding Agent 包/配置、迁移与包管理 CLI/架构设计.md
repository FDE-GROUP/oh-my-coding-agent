模块由三个职责清晰的文件组成，依赖方向单向：package-manager-cli.ts → config.ts → 工具层。
- config.ts 是纯配置与路径解析层：启动时读取 package.json 中的 `piConfig` 派生 `PACKAGE_NAME`/`APP_NAME`/`CONFIG_DIR_NAME`/`VERSION`；通过 `getPackageDir()` 区分 Bun 二进制、Bun runtime、esbuild 打包 Node 与源码三种运行形态，并暴露 `getAgentDir()` 及其下的 `auth.json`/`settings.json`/`models.json`/`tools`/`bin`/`prompts`/`sessions` 等路径；同时实现安装方法检测（npm/pnpm/yarn/bun/bun-binary）与自更新命令生成器（`getSelfUpdateCommand`/`makeConfiguredSelfUpdateCommand`），并通过 `detectInstallChange` 感知进程内安装被外部替换。
- migrations.ts 是启动期一次性迁移层：集中调用 `migrateAuthToAuthJson`（oauth.json/settings.json apiKeys → auth.json）、`migrateSessionsFromAgentRoot`（扁平 .jsonl → sessions/<cwd-hash>/）、`migrateToolsToBin`（fd/rg 从 tools/ 迁到 bin/）、`migrateKeybindingsConfigFile`、`migrateExtensionSystem`（commands→prompts、hooks/tools 废弃警告），统一由 `runMigrations(cwd)` 编排并返回 `deprecationWarnings`。
- package-manager-cli.ts 是对外 CLI 入口：导出 `handleConfigCommand` 与 `handlePackageCommand`，内部通过 `parsePackageCommand` 将 args 解析为 `PackageCommandOptions`，再委托 `DefaultPackageManager` 执行 install/remove/update/list；self-update 分支按优先级选择：用户配置的 `PI_SELF_UPDATE_COMMAND` → 受管安装（`PI_MANAGED_INSTALL_ROOT` + `managed-install.json` schema v1 releases-v1 layout，使用 lockfile 互斥、staging/releases/current-version 三目录原子切换）→ 基于 `config.ts` 生成的 npm/pnpm/yarn/bun 命令；模型刷新走 `ModelRuntime.refresh` 并带 15s 超时。
依赖边界：本模块不直接读写 JSON 文件以外的持久化格式，所有文件系统 I/O 经 `fs` 同步 API 完成；CLI 输出统一用 chalk 着色，Markdown 渲染通过 `@earendil-works/pi-tui` 的 `Markdown` 主题完成。
