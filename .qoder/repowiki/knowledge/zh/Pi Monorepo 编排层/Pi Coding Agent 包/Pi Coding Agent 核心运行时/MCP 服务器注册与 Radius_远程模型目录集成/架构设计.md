模块由四个职责清晰的文件组成：
- `mcp-servers.ts` 定义 MCP 服务器的配置类型（`McpStdioServerConfig` / `McpHttpServerConfig` / `McpOAuthConfig`），在 `@earendil-works/pi-mcp` 的共享字段之上叠加 pi 自有字段（`exposure`、`toolExposure`、`description`、`timeout`、`auth.provider`），并提供 `validateMcpServerConfig`、`createToolNameMatcher`、`getMcpToolExposure`、`isClientMetadataDocumentCallback` 等纯函数；同时维护 `McpServerRegistry` 类，供扩展通过 `pi.registerMcpServer()` 按 extensionPath 隔离地注册/注销服务器，并通过可选的 changeListener 触发 `mcp_servers_change`。
- `radius.ts` 仅暴露常量（`RADIUS_PROVIDER_ID`、`ENV_RADIUS_GATEWAY`、`RADIUS_MCP_URL`）和 `getRadiusGatewayUrl()`，作为 Radius 网关地址的唯一来源。
- `radius-mcp.ts` 基于 `loadMcpConfig` 读取全局 `mcp.json`，生成 `planRadiusMcpServer` 计划：若已存在指向同一 Radius MCP URL 且 auth.provider 相同的条目则复用，否则构造新条目（名称去重使用 `mcpNamespace`），并以 `auth: { provider }` 替换 OAuth 登录。
- `remote-catalog-provider.ts` 实现两个装饰器工厂 `withRemoteCatalog` 与 `withPersonalizedCatalog`，包装任意 `Provider`，从 `https://pi.dev/api/models/providers/{id}?types=chat,image,classifier` 拉取模型目录，结合本地持久化（`ModelsStoreEntry`）、ETag/Last-Modified 缓存与 4 小时刷新间隔，将动态模型合并到静态内置模型之上。
依赖方向单向：`radius-mcp.ts` → `radius.ts` + `mcp-servers.ts`；`remote-catalog-provider.ts` 独立于 MCP 层，仅依赖 `@earendil-works/pi-ai` 的 Provider 抽象。
