- 每个可序列化设置字段在 `SettingsSchema` 中以 `Type.Optional(Type.Xxx({ default: SETTINGS_DEFAULTS.xxx }))` 形式声明，默认值统一从 `SETTINGS_DEFAULTS` 引用而非字面量重复。
- `SettingsManager` 的 setter 遵循固定三件套：更新内存对象 → `markModified(field, nestedKey?)` → `save()`，由 `persistScopedSettings` 根据已标记字段做增量写回。
- 对全局/项目两种作用域的 I/O 一律通过 `storage.withLock(scope, ...)` 包装，避免直接调用 fs 读写，从而复用同一份加锁逻辑。
- JSON 文件加载路径统一为 `stripBom(JSON.parse(...))`，并在 `migrateSettings` 中集中处理旧字段名（如 `queueMode→steeringMode`、`websockets→transport`、`retry.maxDelayMs→retry.provider.maxRetryDelayMs`）。
- 配置值解析采用前缀约定：以 `!` 开头视为 shell 命令，否则作为 `$VAR`/`${VAR}` 模板解析，并通过 `commandResultCache` 进程级缓存命令输出。
