模块按职责拆分为四个层次：
- 类型与默认值层：`settings-schema.ts` 使用 TypeBox (`Type.Object`/`Type.Union`/`Type.Literal`) 声明 `SettingsSchema`，并导出 `Settings` 等 TS 接口；`settings-defaults.ts` 集中定义 `SETTINGS_DEFAULTS`，被 schema 的 `.default` 与运行时 getter 共同引用，保证 JSON Schema 与运行时默认值同源。
- 存储抽象层：`settings-manager.ts` 定义 `SettingsStorage` 接口及 `FileSettingsStorage`（基于 `proper-lockfile` 实现跨进程同步的 `settings.json` 读写）和 `InMemorySettingsStorage`（测试用），通过 `withLock(scope, fn)` 原子读取-计算-写入。
- 管理器层：`SettingsManager` 维护 global/project 两套 Settings，启动时分别 tryLoadFromStorage 并记录错误，随后 `deepMergeSettings` 递归合并；提供 `get*`/`set*` 访问器，修改后通过 `markModified` + `enqueueWrite` 串行写回磁盘，支持嵌套字段级增量持久化。
- 诊断与辅助层：`settings-diagnostics.ts` 将 `drainErrors()` 转为 `AgentSessionRuntimeDiagnostic`；`resolve-config-value.ts` 独立解析以 `!` 开头的 shell 命令或 `$VAR/${VAR}` 模板（带进程级命令结果缓存）；`defaults.ts` 暴露 `DEFAULT_THINKING_LEVEL` 等与 settings 无关的常量。
依赖方向单向：schema → defaults；manager → schema/default；diagnostics → manager；resolve-config-value 不反向依赖 manager。
