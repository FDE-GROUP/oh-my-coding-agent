测试代码按用途分为四层：
- 根目录扁平的 `*.test.ts` 文件针对具体模块（如 `auth-*`、`mcp-*`、`model-*`、`tools.*`、`compaction.*`、`interactive-mode-*`）进行细粒度单元测试。
- `suite/` 是新的基于 `harness.ts` 的集成测试集，围绕 `AgentSession` / `AgentSessionRuntime` 构建端到端场景；`suite/regressions/` 以 GitHub issue 编号命名回归用例，遵循 README 中禁止使用真实 API key / 网络调用的规则，统一通过 `createHarness()` + faux provider 驱动。
- `session-manager/` 对 `src/core/session-manager.ts` 的子能力（build-context、file-operations、labels、load/save-entry、migration、tree-traversal）分别给出独立测试文件。
- `mcp-conformance/` 是一个独立的 Node CLI（`run.ts`），通过 `npx @modelcontextprotocol/conformance@0.2.0-alpha.11` 拉取官方 MCP 一致性套件，用 `client.ts` 作为被测客户端，将结果与 `baseline.json` 比对，支持 `--mode` / `--scenario` / `--update-baseline` 参数。
- `fixtures/` 存放 SKILL.md、JSONL 会话、fake external editor 等静态数据；`suite/mcp-oauth-server.ts` 提供本地 OAuth 服务器供 MCP OAuth 测试使用。
依赖方向单向指向被测源码 `packages/coding-agent/src/*`，并通过 `utilities.ts`、`model-runtime-test-utils.ts`、`test-harness.ts`（旧 harness，新 suite 应优先用 `suite/harness.ts`）共享测试基础设施。
