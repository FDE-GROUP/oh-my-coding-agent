模块按职责分为三层：
- 类型与契约层（`types.ts`）：定义 `CredentialStore`（带 `modify` 序列化写锁的凭证存储）、`ApiKeyAuth`/`OAuthAuth`/`ProviderAuth` 三种 provider 插件接口、`AuthContext`/`AuthInteraction` 等注入点，以及 `ModelAuth`/`AuthResult` 等结果类型。
- 解析与协调层（`resolve.ts`、`context.ts`、`credential-store.ts`、`helpers.ts`）：`resolveProviderAuth` 按「覆盖 > 已存凭证 > 环境/文件」优先级选择 apiKey 或 oauth；OAuth 路径通过 `refreshStoredOAuthCredential` 在 `CredentialStore.modify` 上实现双重检查锁刷新，默认保留 5 分钟余量并抛出 `ModelsError`。
- Provider 实现层（`oauth/*.ts`）：每个提供商一个文件（anthropic/openai-codex/openai-chatgpt/github-copilot/openrouter/kimi-coding/meta/xai/radius），统一导出 `*OAuth: OAuthAuth`；`load.ts` 通过动态 `import()` + `registerBundledOAuthFlowLoaders` 支持浏览器端按需加载与 Bun 静态打包。

共享基础设施：`callback-server.ts` 基于 `node:http` 启动本地回调服务器处理授权码回跳，并与 `waitForCallbackOrManualInput` 协作提供手动粘贴回退；`device-code.ts` 实现 RFC 8628 Device Code 轮询（含 slow_down 指数退避）；`pkce.ts` 用 Web Crypto API 生成 verifier/challenge；`trusted-url.ts` 校验回调 URL 白名单。依赖方向单向：provider 实现 → 共享基础设施 → `types.ts`，不反向引用解析层。
