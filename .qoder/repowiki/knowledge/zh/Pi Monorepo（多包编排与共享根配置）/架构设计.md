根目录作为 monorepo 编排层，不承载业务逻辑，而是把各子模块串联起来：
- 依赖方向由顶层 `build` 脚本硬编码顺序体现（telemetry → schema → tui → codemode → mcp → ai → agent → coding-agent），底层能力库先于上层编排层编译。
- 所有子包继承根 `tsconfig.base.json`（ES2024 + Node16 moduleResolution + strict + verbatimModuleSyntax）与 `vitest.base.ts`（集中声明 `@earendil-works/*` 到源码路径的 alias），跨包引用统一走命名空间而非相对路径。
- 发布流程由 `scripts/publish.mjs` / `scripts/release.mjs` 驱动，配合 husky pre-commit 钩子与 `biome.json` 统一代码风格；`flake.nix` 提供可复现的开发环境。
- `evals_harness` 子模块通过根入口 `npm run eval --workspace=@earendil-works/pi-evals` 触发评估套件，是根脚本对子包的唯一编排入口。
