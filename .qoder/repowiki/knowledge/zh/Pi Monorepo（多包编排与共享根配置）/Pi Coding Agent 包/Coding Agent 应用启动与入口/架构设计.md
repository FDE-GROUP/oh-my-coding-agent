模块由三个并列的入口文件组成，职责清晰分层：
- `cli.ts` 是 Node 可执行脚本（`#!/usr/bin/env node`），仅调用 `setupCli()` 并转发 `process.argv.slice(2)` 到 `main()`，把 CLI 注册逻辑下沉到 `./cli/setup.ts`。
- `rpc-entry.ts` 是 RPC 子进程入口，设置 `PI_CODING_AGENT`/`AI_AGENT` 环境变量、屏蔽 `process.emitWarning`、配置 HTTP dispatcher，并以 `--mode rpc` 重新调用 `main()`，使同一份业务逻辑同时服务交互式 CLI 和 JSON-RPC 子进程。
- `main.ts` 是真正的引导核心：先处理 `auth`/`package`/`config`/`mcp` 等一次性命令，再解析参数、决定 `AppMode`（interactive/print/json/rpc）、创建 `SessionManager`、通过 `createAgentSessionRuntime` + `createAgentSessionServices` 构建运行时，最后根据模式分发到 `modes/index.ts` 中的 `runPrintMode` / `runRpcMode` / `InteractiveMode`。
依赖方向单向向外：入口 → main → cli/* 子命令、core/* 运行时、extensions/*、modes/*；main 不反向被业务模块引用，仅作为进程边界。
