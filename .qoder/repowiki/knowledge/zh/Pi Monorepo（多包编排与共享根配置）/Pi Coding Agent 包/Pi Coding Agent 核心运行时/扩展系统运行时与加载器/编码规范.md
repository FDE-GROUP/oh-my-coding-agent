- 扩展 API 方法统一以 `assertActive()` 开头检查 runtime 是否仍有效，防止 session 替换或 reload 后继续使用过期上下文。
- 扩展注册类 API（registerTool/registerCommand/registerFlag 等）在 loading 阶段写入 pending 队列，由 `createExtensionAPI` 返回的 `commit()` 一次性提交，失败时走 `discard()` 清理。
- 事件处理采用 snapshot-event-handlers 模式：分发前复制 handlers 数组，避免扩展在回调中修改自身 handler 列表导致迭代错乱。
- 对外暴露的公共类型集中在 `types.ts`，`index.ts` 只做 type-only re-export，不重复声明类型。
- 对宿主能力的访问通过闭包 getter（如 `getModel`、`getScopedModels`、`isIdleFn`）而非直接字段引用，使 `bindCore()` 更新后新创建的 context 能观察到最新实现。
