模块按职责拆分为四个层次：
- 类型契约层 `types.ts`：集中定义 Extension / ExtensionContext / ExtensionUIContext / ToolDefinition / 各类 Session/Agent/Tool 事件等所有对外暴露的类型，是扩展作者的唯一 API 文档来源。
- 加载层 `loader.ts` + `jiti-loader.ts` / `jiti-static-loader.ts` + `virtual-modules.ts`：基于 jiti 动态导入扩展工厂函数；在 Node Sea/Bun/打包二进制模式下通过 `VIRTUAL_MODULES` 虚拟模块映射到宿主包，否则使用别名表解析 `@earendil-works/pi-*` 和 `typebox`；支持项目级 `extensions/`、全局 `agentDir/extensions/` 与显式路径三种发现策略，并通过 `extensionCache` 按 cwd/generation 缓存已加载的 factory。
- 运行层 `runner.ts`：`ExtensionRunner` 持有 extensions、runtime、uiContext 与 core action 回调，负责事件分发、MCP server 变更通知、快捷键冲突检测、命令去重、工具渲染解析链、会话边界草稿收集等；通过 `bindCore()` / `bindCommandContext()` / `setUIContext()` 三阶段绑定外部能力。
- 适配层 `wrapper.ts`：将 `RegisteredTool` 包装成 `AgentTool`，统一注入 `ExtensionToolContext`。
依赖方向单向：loader → runner → types；runner 反向依赖上层 agent-core/session-manager/model-registry 等核心子系统，但扩展本身只看到 types 暴露的接口。`index.ts` 作为聚合入口，仅 re-export loader/runner/types/wrapper 的公开符号。
