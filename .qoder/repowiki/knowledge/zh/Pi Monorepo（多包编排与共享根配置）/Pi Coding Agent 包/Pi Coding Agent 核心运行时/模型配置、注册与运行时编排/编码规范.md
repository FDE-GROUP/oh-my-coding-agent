- 配置对象通过 TypeBox schema 声明后由 `Compile` 编译为校验器，并以 `deepFreeze(structuredClone(...))` 返回不可变快照。
- Provider 组合采用三层叠加顺序：内置 Provider → models.json → 扩展 `ProviderConfigInput`，每层通过独立的 `apply*` 函数处理后再合并。
- 异步状态更新统一通过序列号 (`availabilityRefreshSeq`/`errorSeq`/`providerAvailabilitySeq`) 丢弃过期刷新结果，避免竞态写入。
- 凭据相关操作（login/logout/setRuntimeApiKey/removeRuntimeApiKey）经 `enqueueCredentialOperation` 串行化并按 providerId 去重，再调用 `synchronizeCredentialState` 重建 provider 与快照。
- 模型引用解析统一返回联合类型 `{ status: 'resolved' | 'ambiguous' | 'not-found', ... }`，歧义时附带候选列表与 `usableCount`，由调用方决定错误提示。
- 虚拟模型通过固定 `api = "pi-virtual"` 标识并在 `withVirtualModels` 中从物理模型列表中过滤掉同名 chat 模型，确保路由前不会落到真实 provider。
