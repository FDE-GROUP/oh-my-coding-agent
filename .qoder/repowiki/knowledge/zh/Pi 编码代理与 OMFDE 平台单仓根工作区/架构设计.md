仓库以 `pnpm-workspace.yaml` 将 `packages/*`、`apps/*`、`extensions/*` 及若干 examples 纳入同一工作区，子包通过 `@earendil-works/pi-*` / `@omfde/*` 命名空间互相引用。

- 依赖方向自底向上：`pi-schema` → `pi-telemetry` → `pi-tui` → `pi-codemode` → `pi-mcp` → `pi-ai` → `agent_core` → `coding_agent`；`omfde_cli` 仅薄包装 pi 可执行文件，`pi_web` 在运行时通过 RPC 子进程复用 coding-agent。
- 根 `package.json` 的 `build`/`check`/`test`/`release:*` 等脚本按拓扑顺序调用各包的 `pnpm --filter`，是跨子模块的唯一编排入口。
- 共享基础设施集中在根目录：`tsconfig.base.json`（ES2024 + Node16 + strict + verbatimModuleSyntax）被各包继承；`biome.json` 统一格式化与 lint 规则并包含自定义 Grit 插件用于模型类型比较；`vitest.base.ts` 提供测试基线。
- 代码生成链路贯穿多个子模块：`pi-ai` 通过 `generate-models`/`hydrate:model-data`/`generate-model-catalog` 产出模型注册表，根脚本 `diff/model-catalog` 与 `check:model-catalog-compat` 校验其稳定性。
- 质量门禁由根 `scripts/*.mjs` 集中实现（secrets、pinned-deps、runtime-deps、ts-imports、entry-graphs、browser-smoke、tsdoc），`prepublishOnly` 强制先 clean→build→check 再发布。
