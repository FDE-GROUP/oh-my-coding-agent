docs 目录按文档类型划分为三个互不依赖的子目录：
- `explains/`：以编号顺序组织的代码阅读笔记（00–27），从仓库基线、关键路径、session/transcript、provider、tools、compaction、MCP、TUI 到 schema 与验证脚本；`validation/` 子目录提供可运行的 TypeScript 验证脚本（validate-events.ts、validate-projection.ts、validate-tool-call.ts），用 faux provider 驱动 AgentSession 并产出 `25-validation.md` 中的结果。
- `rads/`：需求描述文档目录，通过复制 `TEMPLATE.md` 生成 `<slug>.md`，并与 `specs/vision.md` 的 Vision 对齐。
- `specs/`：项目宪法与工作流，包含 `vision.md`（目标、边界、阶段、决策记录）、`workflow.md`（RAD → Spike → Plan → 验证闭环）和 `tsdoc-comment-standards.md`（TypeScript 注释规范与检查门禁）。

依赖方向单向：RADS 与 specs 是上游约定，explains 是对现有代码的理解产物；三者共同构成 vision → RAD → plan → explains 的文档闭环。
