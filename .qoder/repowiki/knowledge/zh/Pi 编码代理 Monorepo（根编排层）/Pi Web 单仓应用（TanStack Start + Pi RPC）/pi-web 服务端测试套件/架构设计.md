测试目录采用单文件一组用例的结构：`jsonl.test.ts` 通过 Vitest 验证 `createJsonlSplitter` 的分片、CRLF 剥离与换行符边界行为；`runtime.test.ts` 通过真实子进程启动 `node_modules/.bin/pi`，以 `--no-extensions -e ./faux-extension.ts --provider fauxspike --model faux-1` 参数注入假后端，覆盖 SessionRuntime 的初始化/命令流/快照/恢复以及 RuntimeManager 的空闲回收。`faux-extension.ts` 是独立的扩展入口，借助 `@earendil-works/pi-ai/compat` 的 `registerFauxProvider` 与 `fauxAssistantMessage` 提供固定响应，并注册 `/uispike` 命令触发 `ctx.ui.confirm` 以验证 UI 子协议。测试依赖方向单向指向 `../src/server/*`，不引入业务逻辑。
