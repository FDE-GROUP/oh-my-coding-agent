- 每个 OAuth 厂商实现独立为一个文件并导出命名函数（如 `anthropicOAuth`、`openaiCodexOAuth`），由 `oauth/load.ts` 统一通过动态 import 或打包器注入的加载器获取。
- 对 `CredentialStore` 的所有写操作（login、refresh、logout）都通过 `modify(providerId, fn)` 序列化执行，避免并发请求重复刷新同一 token。
- 长耗时操作接受可选的 `AbortSignal`，并在关键分支调用 `signal.throwIfAborted()` 或使用 `operationSignal`/`raceWithAbortSignal` 包装，使取消能传播到存储与网络层。
- 错误统一包装为 `ModelsError` 并附带语义 code（"auth"、"oauth"），对外只暴露错误码而不泄露底层堆栈。
- API Key 解析遵循「存储键优先 → 环境变量轮询」顺序，并通过 `envApiKeyAuth` 工厂复用，非标准来源（AWS profiles、ADC 文件）则编写自定义 `ApiKeyAuth.resolve`。
- OAuth 实现拆分为 `login`（获取 refresh/access）、`refresh`（续期）、`toAuth`（从凭据推导请求头）三段，由 `resolve.ts` 持有刷新锁与有效期检查逻辑。
