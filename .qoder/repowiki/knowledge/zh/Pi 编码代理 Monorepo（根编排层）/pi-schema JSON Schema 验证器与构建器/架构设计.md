模块以 `src/index.ts` 为对外入口，按职责拆分为若干独立文件：
- `builders.ts`：返回纯 JSON Schema 对象的构建函数（`str/num/int/obj/tuple/union/recursive/bytes/bigint` 等），通过 TypeScript 泛型 + `STATIC` 符号将 schema 与其接受的静态类型绑定，并兼容 TypeBox 1.x 的 `~kind`/`~unsafe` 标记。
- `validator.ts`：导出 `compile()` 工厂，根据 `coerce` 选项返回 `Validator` 或 `CoercingValidator`；`check` 是布尔快速路径，`errors` 惰性使用 `Explainer`，`validate` 组合二者。
- `compiler.ts`：核心编译器，把 schema 编译成闭包检查函数；遇到 `$dynamicRef` 时抛出 `RESTART` 信号重新以动态作用域模式编译一次。
- `coerce.ts`：三阶段强制转换（可选 null 丢弃 → 基于 keyword 的结构化转换 → Ajv 风格的 primitive coercion）。
- `explain.ts`：在首次失败时构建错误解释器，输出带 JSON Pointer path 的错误列表。
- `resolver.ts` / `annotations.ts` / `checks.ts` / `shared.ts` / `types.ts`：辅助解析 `$ref`/`$anchor`/`$dynamicRef`、注解处理、深度相等与共享类型。
- `formats/index.ts`：可选子入口，聚合 `typebox/` 下每个 format 的 `FormatCheck` 实现（date/email/uri/uuid/ipv4/ipv6/json-pointer/regex/url 等），未导入时 `format` 仅作为注解。
依赖方向单向：`index → validator → compiler/explain/coerce/resolver`，`formats` 仅依赖 `types.ts` 中的 `FormatCheck` 接口，不反向依赖编译器。测试套件 `test/fixtures/json-schema-test-suite/` 包含官方 suite 与 meta-schemas，`vitest.config.ts` 驱动运行。
