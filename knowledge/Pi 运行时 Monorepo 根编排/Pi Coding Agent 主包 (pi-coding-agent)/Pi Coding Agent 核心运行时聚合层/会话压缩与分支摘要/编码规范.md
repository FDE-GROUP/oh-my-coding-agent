- 所有对 LLM 的摘要调用都经过 `completeSummarization` 包装，统一设置 `cacheRetention: 'none'` 并通过 `retryAssistantCall` 处理瞬态失败。
- 摘要输出前用 `getSummarizationFailure` 检查 `stopReason`（error/length），并对含 `toolCall` 的内容直接拒绝，防止摘要生成器执行工具。
- 文件变更追踪统一通过 `createFileOps` + `extractFileOpsFromMessage` + `computeFileLists` + `formatFileOperations` 四步完成，并将 read/edited/written 归并为 `<read-files>` / `<modified-files>` XML 片段追加到摘要末尾。
- 发送给模型的消息先经 `convertToLlm` 转为标准 Message，再用 `serializeConversation` 序列化为文本，避免模型把输入当作需要续写的对话。
- token 估算采用 `chars / 4` 启发式（`estimateTokens`），并按 message.role 分 switch 分支分别统计 text/thinking/toolCall/image/bashExecution 等块。
- 可配置项（如 `DEFAULT_COMPACTION_SETTINGS`、`reserveTokens`、`keepRecentTokens`）集中声明为常量对象，供 `shouldCompact` 与调用方读取。
